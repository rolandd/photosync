## 2026-05-18 - [Buffered I/O Regression]
**Learning:** Adding `BufReader`/`BufWriter` (128KB) to `std::io::copy` caused a ~17% performance regression compared to bare `File` handles. `std::io::copy` and `std::fs::copy` likely leverage kernel-side optimizations like `copy_file_range` or `splice` on Linux, which userspace buffering interferes with.
**Action:** Avoid wrapping `File` handles in `BufReader`/`BufWriter` for file-to-file copies unless there is a specific need for userspace processing. Prefer `std::fs::copy` or bare `std::io::copy`.
## 2026-05-19 - [OsStr vs to_string_lossy in File Traversals]
**Learning:** Using `to_string_lossy()` on `e.file_name()` for every entry during file system traversal (e.g., `WalkDir`) causes significant overhead due to memory allocation and UTF-8 validation. Pre-allocating `OsString` values outside the loop and performing direct `OsStr` comparisons avoids this overhead entirely, operating up to ~5x faster.
**Action:** When filtering files or checking paths in a hot loop (like `WalkDir::filter_entry`), avoid converting `OsStr` to `String` (e.g. `to_string_lossy()`). Convert your filter criteria to `OsString` *before* the loop and compare raw `OsStr` references.
